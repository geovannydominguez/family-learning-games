# Family Learning Games — Architecture v0.8

**Version:** v0.8

**Phase:** FASE 8 — Audio / imágenes

**Status:** Proposed for implementation

**Date:** 2026-10-03

**Baseline:** Family Learning Games v0.7.1

---

## 1. Purpose

v0.8 adds a small, child-friendly media layer to the existing Family Learning Games experience:

1. a player can listen to the current question and its answer options;
2. a question can optionally display an educational image;
3. audio and images remain optional enhancements and never become prerequisites for playing;
4. the existing v0.7.1 AI text-generation pipeline remains unchanged.

The release deliberately avoids turning media support into another long-running synchronous AI pipeline.

---

## 2. Baseline preserved from v0.7.1

The following architectural decisions remain valid:

- Next.js remains the frontend.
- The app remains an installable **online-first PWA**.
- AWS Amplify Hosting remains presentation-only infrastructure.
- `GameApiClient` remains the only frontend boundary for backend operations.
- API Gateway HTTP API remains the public backend entry point.
- The existing `family-learning-games-backend` Lambda remains the only application Lambda in v0.8.
- DynamoDB remains the persistence layer for:
  - games;
  - game sessions;
  - players.
- Amazon Bedrock remains responsible for AI text generation and validation.
- Generator and Validator remain independent invocations.
- Claude Sonnet 4.6 remains a deployment configuration concern, not a Domain/Application concern.
- The v0.7.1 execution-budget protection for the AI generation pipeline remains untouched.
- Domain remains AWS-independent.
- Application remains provider-independent.
- AI-produced data remains untrusted and must be validated before persistence or presentation.

v0.8 must not regress or bypass these boundaries.

---

## 3. Scope decision

### 3.1 Audio

Question audio is synthesized **on demand** using Amazon Polly.

The application sends no arbitrary text from the browser to Polly. The client identifies the persisted game/question, and the backend builds the speech text from trusted persisted game content.

One audio asset contains:

1. the question text;
2. the answer options in their current displayed order.

The synthesized MP3 is cached in private S3 storage and reused while its cache entry remains valid.

### 3.2 Images

v0.8 supports **optional controlled question images**.

Images are not generated by an AI model at runtime in this release.

Allowed image sources for v0.8 are application-controlled assets prepared by the project and stored in the private media bucket.

Generated games are valid even when no suitable image exists.

Runtime image generation, remote image search, arbitrary external URLs, family photo uploads and user-generated image uploads are explicitly deferred.

## 5. New AWS infrastructure

### 5.1 Private media S3 bucket

Add one dedicated S3 bucket for runtime/application media.

Example logical name:

```text
GameMediaBucket
```

Example physical naming convention:

```text
<env>-family-learning-games-media
```

The bucket must:

- block all public access;
- disable public ACL usage;
- use server-side encryption;
- use least-privilege IAM;
- never be configured as a public website;
- expose objects only through short-lived pre-signed GET URLs generated by the backend;
- have CORS limited to the application origins required to play media;
- use environment-appropriate removal/retention policies: the default development environment (`environment=dev`) uses `RemovalPolicy.DESTROY` with `autoDeleteObjects` (CDK's deploy-time cleanup handler, never on the request path) so `cdk destroy` leaves no orphaned bucket; `environment=prod`/`production` uses `RemovalPolicy.RETAIN` without the cleanup handler.

Suggested prefixes:

```text
images/
audio-cache/
```

### 5.2 Audio cache lifecycle

`audio-cache/` contains derived, reproducible content.

It may use an S3 lifecycle expiration policy, for example 30 days.

Expiration is safe because missing audio can be regenerated.

`images/` must not use the audio cache lifecycle policy.

## 6. Domain model

The Domain must not know about:

- S3;
- bucket names;
- object keys;
- pre-signed URLs;
- Polly;
- voice IDs;
- MP3;
- AWS SDK types.

### 6.1 Question image reference

Add optional media metadata to a question through a provider-independent logical reference.

Conceptual model:

```ts
type QuestionMedia = {
  image?: QuestionImage;
};

type QuestionImage = {
  assetId: string;
  altText: string;
};
```

A question remains valid without `media`.

`assetId` is a logical application identifier, not an S3 URL.

Example:

```json
{
  "id": "question-1",
  "text": "¿Cuál de estos animales vive en el océano?",
  "media": {
    "image": {
      "assetId": "animals/dolphin-01",
      "altText": "Un delfín nadando en el océano"
    }
  }
}
```

### 6.2 Accessibility requirement

Every image must have meaningful `altText`.

Decorative images should not be modeled as learning media.

The image must not contain the answer key or visually reveal the correct answer unless the educational question explicitly depends on identifying the image.

## 7. Application ports

### 7.1 `SpeechSynthesizer`

Application depends on an abstraction similar to:

```ts
interface SpeechSynthesizer {
  synthesize(command: {
    text: string;
    language: string;
  }): Promise<Uint8Array>;
}
```

Exact byte/container types may be adapted to the existing code style, but Application must not import Polly SDK types.

### 7.2 `MediaObjectStore`

Application uses a provider-independent media storage contract.

Conceptually:

```ts
interface MediaObjectStore {
  exists(assetKey: string): Promise<boolean>;
  put(assetKey: string, content: Uint8Array, contentType: string): Promise<void>;
  createReadUrl(assetKey: string, expiresInSeconds: number): Promise<string>;
}
```

Infrastructure provides the S3 implementation.

### 7.3 `QuestionImageResolver`

Image resolution must translate a logical `assetId` into a media object without exposing S3 naming rules to Domain.

A missing image must degrade gracefully to a text-only question.

## 8. HTTP API

### 8.0 HTTP contract convention (implemented)

v0.8 reuses the existing Family Learning Games HTTP contract unchanged. It does **not** introduce a `{ "code", "message", "data" }` envelope or any second response format:

- success responses return the endpoint-specific JSON body directly;
- every error returns `{ "error": { "code": "<APPLICATION_ERROR_CODE>", "message": "<safe message>" } }`;
- existing endpoints keep their previous request/response shapes; v0.8 only adds optional fields and one route.

### 8.1 Question audio

Add:

```http
POST /games/{gameId}/questions/{questionId}/audio
```

Request body: empty, `null`, or `{}`. Any field (for example `text`, `ssml`, `voiceId`, `outputFormat`), a non-object JSON value, or invalid JSON is rejected.

The client must not submit speech text.

Successful response (`200 OK`):

```json
{
  "audioUrl": "<short-lived-signed-url>",
  "expiresAt": "2026-10-04T03:00:00.000Z"
}
```

Error responses (existing error contract):

| Status | `error.code` | When |
| --- | --- | --- |
| 400 | `INVALID_REQUEST` | body contains any field / is not an empty JSON object, or a path identifier is malformed (allowed: `[A-Za-z0-9._~-]`, 1–128 chars) |
| 404 | `RESOURCE_NOT_FOUND` | unknown game (`"Game was not found."`) or question (`"Question was not found."`) |
| 422 | `QUESTION_AUDIO_UNSUPPORTED` | nothing speakable, or speech text exceeds the bound |
| 502 | `QUESTION_AUDIO_FAILED` | Polly or S3 failure (`"Question audio is temporarily unavailable."`), no provider details |
| 503 | `QUESTION_AUDIO_DISABLED` | backend deployed without a media bucket |

Example:

```json
{ "error": { "code": "QUESTION_AUDIO_FAILED", "message": "Question audio is temporarily unavailable." } }
```

The backend:

1. loads the game;
2. locates the question;
3. derives speech text from the persisted question and answer order;
4. calculates a deterministic audio cache key;
5. reuses a cached object when available;
6. otherwise invokes Polly;
7. stores the MP3 in `audio-cache/`;
8. returns a short-lived signed URL.

### 8.2 Question image URL

Public game/session question DTOs expose resolved image presentation data in an additive, optional `media` field:

```json
{
  "media": {
    "image": {
      "url": "<short-lived-signed-url>",
      "altText": "Un delfín nadando en el océano"
    }
  }
}
```

The pre-existing public `image?: string` field (part of the public question DTO since v0.2, a free-form reference that the AI Generator may emit) is **not** reused or retyped. It keeps passing through unchanged for backward compatibility and is not a controlled v0.8 asset; the v0.8 frontend renders only `media.image`.

The persisted game continues to store the logical `assetId`, not the signed URL.

Signed URLs are runtime presentation data and must never be persisted in DynamoDB.

### 8.3 Compatibility

All new media fields are optional.

Existing consumers that ignore them continue to work.

Existing seeded/generated games without media remain valid.

## 9. Audio cache key

Audio must not be keyed only by `questionId`.

A deterministic cache key should change when spoken content or speech configuration changes.

Conceptually:

```text
sha256(
  normalizedSpokenText
  + language
  + voiceConfigurationVersion
)
```

Example object key:

```text
audio-cache/v1/<hash>.mp3
```

Do not place question text, player names, topics or other readable personal/contextual data in object keys.

Implemented key: `audio-cache/<AUDIO_CACHE_VERSION>/<sha256([version, language, voice profile, text])>.mp3`.

Known limitation (accepted for v0.8): two concurrent cache-miss requests for the same question may both invoke Polly. Both write the same deterministic object, so the result is identical and the extra cost is bounded; no lock, queue or idempotency table is introduced.

## 10. Speech construction

The backend constructs a deterministic spoken representation.

Example:

```text
¿Cuál de estos animales vive en el océano?
Opción 1: León.
Opción 2: Delfín.
Opción 3: Caballo.
Opción 4: Águila.
```

Requirements:

- preserve the displayed answer order;
- never announce which answer is correct;
- do not include hidden answer metadata;
- normalize unsafe/control characters;
- enforce a maximum speech length;
- use the single v0.8 speech profile, set by deployment configuration and not selectable: voice `Lupe`, engine `neural`, language `es-US` (sent as Polly `LanguageCode`), output `mp3`. Spoken labels (`Opción N`) are Spanish. Other languages/variants (including `es-MX`, `es-ES`), voice selection and i18n are out of scope for v0.8;
- do not accept SSML from the browser or from persisted AI output.

v0.8 should prefer plain text synthesis. SSML is unnecessary for the first implementation.

## 11. Images

### 11.1 Controlled catalog

Images are registered as controlled application assets.

A minimal catalog can map:

```text
assetId → object key / metadata
```

The catalog may be implemented through static application configuration or a small infrastructure adapter.

A separate DynamoDB table is not required for v0.8.

### 11.2 Validation

Before a game referencing an image is persisted, validate:

- `assetId` syntax;
- `altText` required and bounded;
- no raw external URL;
- no data URI;
- no bucket name/object URL embedded in Domain;
- only known/allowed assets may be resolved.

### 11.3 Generated games

The text Generator is not required to invent image URLs.

For v0.8, the AI text pipeline must not:

- return S3 URLs;
- return arbitrary HTTP image URLs;
- invoke an image model;
- select copyrighted remote images;
- delay game generation waiting for visual media.

If an application-controlled asset mapping exists for the generated topic/category, Application may attach it deterministically outside the AI provider output.

Otherwise the generated game remains text-only.

## 12. Frontend behavior

### 12.1 Audio

Each question screen adds an accessible action such as:

```text
🔊 Escuchar pregunta
```

Behavior:

- audio starts only after explicit user interaction;
- do not autoplay on navigation;
- disable duplicate requests while synthesis/resolution is in progress;
- allow replay after the URL is available;
- show a non-blocking error if audio fails;
- game answering remains available while audio is unavailable.

### 12.2 Images

When `image` exists:

- display it above or near the question;
- preserve responsive sizing;
- prevent layout jumps as much as practical;
- render meaningful `alt`;
- use lazy loading where appropriate;
- do not make the image the only way to understand the question unless the game intentionally tests image recognition.

When image loading fails, the question remains playable.

## 13. PWA behavior

ADR-014 remains valid.

v0.8 does not change the PWA into offline-first.

Service Worker rules:

- continue caching only approved static assets/offline fallback;
- do not blindly cache API responses;
- do not cache short-lived signed S3 URLs as permanent application data;
- do not expose expired media as if it were authoritative;
- backend/API operations remain network-only.

Application-controlled static UI icons may still be part of the normal PWA asset cache.

## 14. Security

### 14.1 S3

Required:

- private bucket;
- block public access;
- bucket-level TLS-only policy where appropriate;
- least-privilege access from the backend Lambda;
- read URLs expire;
- no write pre-signed URLs in v0.8;
- no browser AWS credentials.

### 14.2 Polly

The backend Lambda receives only the minimum `polly:SynthesizeSpeech` permissions required.

Do not grant:

```text
polly:*
```

Application and Domain must not contain IAM/resource identifiers.

### 14.3 Input trust

The audio endpoint accepts only game/question identifiers.

It never accepts arbitrary text to synthesize.

This avoids using Family Learning Games as a general-purpose public TTS proxy.

### 14.4 Logging

Never log:

- full signed S3 URLs;
- synthesized MP3 bytes;
- complete question content unless existing logging policy explicitly allows it;
- answer correctness;
- secrets or AWS credentials.

Structured logs may include:

- correlation ID;
- game/question opaque IDs;
- cache hit/miss;
- synthesis duration;
- media resolution outcome;
- safe error category.

---

## 15. Failure behavior

Media is an enhancement, not a core game dependency.

### Audio failure

Possible causes:

- Polly unavailable;
- S3 error;
- signed URL generation failure;
- browser playback failure.

Result:

- show a safe UI error;
- keep the question playable;
- do not fail or corrupt the game session.

### Image failure

Possible causes:

- missing catalog asset;
- object missing;
- signed URL expired;
- browser network failure.

Result:

- hide/fallback the image;
- preserve `altText` only when useful;
- keep the question playable.


Useful metrics:

- audio cache hit ratio;
- Polly synthesis duration;
- synthesis errors;
- S3 read/signing errors;
- missing image assets.

Do not mix these events with the v0.7.1 Generator/Validator execution-budget telemetry.

## 17. Cost model

v0.8 remains suitable for a small family workload.

Primary new costs:

- Amazon Polly characters synthesized;
- S3 storage;
- S3 GET/PUT requests;
- negligible additional Lambda/API execution.

Audio caching prevents repeated synthesis of identical content.

No image-generation inference cost is introduced in v0.8.

## 20. Resulting architecture principle

v0.8 adds media without changing what a game fundamentally is:

```text
Game
 └── Question
      ├── text
      ├── answers
      └── optional controlled image reference

Question text + answers
        ↓
Application speech service
        ↓
SpeechSynthesizer
        ↓
Amazon Polly
        ↓
private S3 audio cache
        ↓
short-lived signed URL
        ↓
PWA audio player
```

A failure in the media path must never make the core quiz unplayable.
